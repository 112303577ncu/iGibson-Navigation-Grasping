# 2×2 m 場地建圖：目前為靜止局部圖

> 本文為手臂修正前的初期紀錄，已被 [四邊繞行結果](MAPPING_LOOP_2026-10-17.md) 接續；目前已完成監督式繞行建圖，S3讀值已恢復。

使用者授權由場地約右下角開始逆時鐘繞行，最終建立導航巡航路徑。未發底盤速度命令，尚未完成繞行、完整建圖或巡航驗收。

## 開機與阻斷原因

- SSH 172.20.10.3；grasp-service、vision、控制/視覺監督器、ROS、LiDAR 均啟動。初始 MemAvailable 1816 MB，輪命令全零、odom 有效。
- startup_pose=servo_read_failed，chassis_tcp_ready=false。status 指出 S3 讀值無效；home 兩次都明確拒絕、未執行手臂動作。
- 停止監督器與 owner，fuser 確認無序列持有者後，用既有唯讀 bus_probe 做五輪。S3 每輪都有正確 ID 回應，但角度超出範圍。
- 第二次唯讀診斷保留 raw：S3 五次均 3396，依現行 900..3100 對應 180..0°，未取整約 -24.2°。其餘軸約 [90,141,_,1,90,30]。是範圍錯誤，不能當成單純 timeout，也未證明伺服機損壞或校正原因。
- 診斷時無第二 owner。第一次 probe 非零退出導致 shell 未啟動原服務，隨即手動恢復；第二次加入 EXIT trap，診斷後恢復 owner/monitor。兩次 owner 重啟均使 odom 原點重設。
- 未放寬解碼範圍、未偽造巡航位、未用獨立寫入器繞過姿態閘。使用者要求直接歸位後再次送 home，仍被拒絕。
- 最後 maintenance-lock 回 ok=false，不能宣稱已上維護鎖；TCP 原本未啟用，四輪仍零速。

## 已執行的建圖準備與靜態掃描

- 對實機 launch 原字串精確核對並備份後，只將 base_link→laser 前移由 0.10 改為實測 0.13 m。重啟 LiDAR 後直接 ROS TF 確認 x=0.13；本機 launch 同步修改，XML 解析與參數檢查通過。
- 尚未同步一般導航客戶端內的 0.10 m 常數，正式導航前仍須統一；目前未執行這些客戶端。
- 沿用固定自回波 profile，不從當前牆面重新學習；/scan_raw→/scan→前180° /scan_mapping→GMapping。
- 使用既有 g2_demo_mapping.py（180秒上限、systemd 外層200秒、原有RAM限制），無AMCL/map_server競爭節點。只建立靜止局部圖後手動停止，確認無殘留 gmapping/filter。
- 保存 stationary_partial.pgm/yaml 與 PNG 預覽，192×192、2 cm/格；snapshot 中 occupied=287、free=6136。此格網尺寸不是場地量測尺寸。
- 原始/濾波 scan 有限點2020/1995，配對時間戳年齡約0.203秒；odom靜止有效。建圖快照 MemAvailable 1654 MB，停止後1749 MB；是快照，非全程最小值。
- 圖中已見牆線與缺口，但前180°靜止視野不完整，不能據此發布完整閉合導航圖或正式巡航點。

## 後續順序

1. 排除 S3 原始位置超出現行範圍；若需人工處理，先重新接通手臂伺服供電/檢查實際姿態。有效角度恢復後才走常駐 home→stow，確認 TCP 啟用；不續用舊 odom reference。
2. 統一實際使用的導航客戶端 LiDAR 前移13cm，驗證固定濾波與牆面。
3. 重啟建圖，先確認車頭方向及掃描牆距，以實際感測決定逆時鐘路線，分段走完四邊並回到起點；不是僅原地旋轉一圈。
4. 角落缺口保留在原始 SLAM 圖。優先實體補齊掃描高度的牆角；若無法補齊，在獨立導航地圖/成本圖加經確認的虛擬邊界，巡航點放在場內並保留車體包絡與停車距離。不把未知區整片改成可通行。
5. 尺寸核對、保存完整圖，停止GMapping後再開AMCL，建立逆時鐘巡航/投放點路線並驗證重複成功。
