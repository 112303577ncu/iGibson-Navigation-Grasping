# 投放前保留可退出的方向

本版只做離線修改、原始碼測試與地圖驗算，沒有SSH、部署、底盤或手臂動作。
盒位不變，正式巡航採用Claude審查提供的35cm批准mask；須配套地圖與規則，沒有部署。

## 執行順序

1. 持物、travel、停穩與定位確認後，從目前地圖取出牆、紙盒包絡與實際巡航mask。
2. 以5度間隔搜尋72個方向；準備點距盒中心約1m，維持原後相機取得目標的範圍。
   沿用原生 `PLACEMENT_FINAL_X_M/PLACEMENT_AIM_Y_M`，不改放下距離；地圖停點另依紙盒長寬與朝向計算斜向盒深投影。
3. 停點及位置±4cm、角度±8度的27個樣本，都須有60cm內可直退的出口。
   從準備點到停點另取21個位置檢查退路；目標點中心及6／7cm轉向圈都須在巡航mask內。
   整條退出線仍經固定牆與紙盒的原生 `back_path_problem` 檢查。
4. 排序優先最大化最差車體角點牆距，其次較短退距與轉運直線距離。
   依排序用Jetson原生導航做唯讀可達預檢，才執行到準備點的導航及絕對map yaw對正。
   導航與PPO分階段持有TCP，不增加Serial owner。
5. 接近期間，模型的MotorClient在送非零命令前檢查定位permit與預測退路。
   預測0.6秒，平移用請求速度的2.4倍及實測速度較大值作保守界，角速度亦涵蓋實測回授。
   可以用較慢速度保留退路時，只降低原前進速度；否則送stop。不可藉此增加速度、創造轉向或倒車。
   近盒轉向依整個預測弧線保留出口及車體掃掠包絡判斷，不以0.02rad/s限制擋住原生0.30rad/s有效修正。
   角速度保持原請求，不降到馬達無法啟動的速度；旋轉不得更深入固定盒的保守包絡。
6. 原本的相機到達檢查及可選wall-m修正保留；wall-m點動也要經退路檢查。
   **攔截真正的release RPC**，在最後修正之後，重新確認持物狀態、定位與退路。
   已驗證盒位要求距原計畫停點≤10cm；未驗證盒位改用本輪視覺到達及停止map pose推算停點，誤差仍≤10cm。
   原生到達閘、報告時效、候選25cm誤差界及觀測盒包絡檢查全部通過才放開；不把verified改成true。
   不是在模型說到達前預先給一張可無限沿用的放下許可。
7. 放下成功後，沿既有回授退出流程直退，每段最多10cm，三筆新停穩資料通過才續巡航。

## 失敗時的處理

- 定位source age及傳輸延遲的總和超過0.4秒，或owner／boot／map不符，模型送零速等待。
  每階段只開一條唯讀SSH定位串流；capture握手固定時鐘下界，延遲的舊封包不能因剛收到就重新變新。
- 首次TCP連線建立後才檢查permit；連線中斷後只送stop並結束該次接近，不重送連線前已批准的非零速度。
- 進入近盒區前找不到可進可出的方向／可達準備點，就回報NO_REVERSIBLE_DOCK／NO_REACHABLE_DOCK。
- 接近失敗時先停止並關閉本階段模型控制；只在服務確認仍holding、travel與停穩時，直退回可巡航轉向區。
  再排除失敗方向附近10度，最多重新接近一次。第二次失敗亦先嘗試退到合法停點後回報。
- 放下結果不明、空爪卻收到失敗、owner改變等情況不重試手臂，也不以「可能還握著」作假設。
- 使用resident runtime才有同一PC程序內的release攔截；isolated階段在開始投放前拒絕，不默默繞過。

這是降低「放完才發現沒出口」的機制；不能承諾所有狀況都不停車。
定位持續失效、實際滑移超出預算、車體／持物包絡錯誤、硬體損壞或實體退路不成立時，仍必須停止。
低速是否能在目前地墊平順行駛、0.6秒／2.4倍速度預測是否包住實際停止距離，仍需實車量測。

## 入口與版本

```powershell
python integration/g2_prepare_koala.py --output .runtime/koala-e8766f0-review
python grasp/v23/demo.py mission --host <Jetson-IP> --gstreamer <gst-launch-1.0.exe>
```

準備來源固定koala e8766f03。新manifest為schema2，包含MotorClient gate及獨立幾何helper，
並核對placement_dock與PC helper的SHA256；既有schema1目錄要保留並另外準備新目錄。
上述第二個命令會做唯讀實機預檢；本輪沒有執行，實車另須既有real／人在車旁旗標。
`mission-legacy`明確保留舊程式相容用途，不含這套走廊監督。

日後Jetson須配套更新 `deploy/ros/g2_map_patrol.py`（含face-yaw）及既有定位／boundary依賴。
保留其他組員的手臂服務與唯一Serial owner；本次沒有執行部署命令。

紀錄：`mission/placement_corridor.json` 保存候選／準備點／放下許可／持物退出結果；
每階段保存contract；高頻定位state使用系統暫存目錄，階段結束清除，避免OneDrive同步阻塞控制。
最終退出仍在 `post_place_reentry.json`。

## 地圖驗算的界線

離線候選見 [規劃資料](../planning/placement_corridor_2026-10-22/plan.json)。
它使用目前的紙盒候選座標及保守包絡；實際盒位尚未完成精確登錄，沒有把verified改為true。
候選方向只是取樣集合中的排序結果，不是連續空間全域最優或實車通過證明。
原生target到達／相機校正閘保留；這套退出guard不取代紙盒辨識、伸臂包絡或投放落點量測。
若真實盒位與地圖差異超過允許範圍，應重新登錄／校正；若所有方向仍無出口，再移盒並更新地圖。

本次納入紙盒斜向投影後，地圖取樣得到10個候選，排序第一為map yaw20度，即相對房間牆線45.77度。
名義直退出口19cm，位置±4cm／角度±8度樣本最遠25cm；實際退出仍重新計算。
以真實固定版本MotorClient的AST執行無網路測試，原請求0.15m/s被保守降為0.1125m/s，
失效permit送stop，零速不受失效permit阻擋。這不代表實際車速已量測或該方向已實車驗收。
