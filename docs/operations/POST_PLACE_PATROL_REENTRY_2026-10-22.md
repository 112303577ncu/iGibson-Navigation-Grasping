# 放置後退出與下一圈巡航

本輪為本機離線修改，沒有SSH連線、部署或實車移動。

問題是退出與巡航使用不同的完成條件。固定後退20cm不保證中心進入導航遮罩；
即使中心已合法，原生巡航還要求周圍6cm的16個取樣點也合法，才允許原地轉向。
koala `loop-opt-2026-10-21` 的 `Room.exit_distance/mask_exit` 已嘗試找回遮罩的位置，
但檢查的是中心及直退方向上前5cm的點，沒有完整檢查轉向圓周，且實際停點可能有超走或欠走。

## 已加入的退出完成條件

`integration/g2_patrol_reentry.py` 由 `integration/v23_mission_entry.py` 自動載入，
接在同一份koala checkout的 `place_held -> Room.leave -> 下一圈PATROL` 之間。
不覆寫koala的PPO、手臂或近距離倒車程式。

```
放置成功
  -> 確認 holding=false、travel、手臂閒置、四輪零回授、TCP無其他client
  -> 沿目前接近方向直退，每次命令最多10cm；近盒處不先轉向
  -> 每段後重新讀AMCL、輪式里程計及owner/boot/map
  -> 中心、原生6cm圈、額外7cm圈全部在巡航mask內
  -> 連續三筆不同odom時間戳的停穩位置仍符合
  -> PATROL_REENTRY_READY，才進下一圈
```

成功放置後沒有最低固定20cm的要求，已具備接手條件就不再多退。
未夾到糖果時原本為了重新進入相機視野而指定的最低退距仍保留，兩種目的不混用。
進度使用實際輪式里程計，AMCL僅判斷目前地圖位置；不把AMCL座標修正當作車輛已後退。
每次重新規劃剩餘直退距離，而非從名義命令扣固定10cm；已因滑行到達合法退出點時不再補退小餘量。

整條預計退出線及每一段實際命令，仍經koala的 `back_path_problem/back_straight` 檢查牆面與固定投放盒。
規劃最大退距60cm，最後命令滑行留5cm實際量上限；不會因碰到名義距離上限而拒絕承認已安全到達退出點。
另有限制90秒、50次迭代、側漂4cm、航向偏差5°、三次沒有實際進度；任何一項失敗會停車並記錄原因。

定位須新鮮至0.4秒內，平面協方差每軸不超過 `(0.04/3)^2`，速度回授須低於1cm/s與0.02rad/s。
這些是定位品質及停穩閘，不能取代物理量測。手臂仍握物、位置未知、owner變更、實體退路不足時，不放行下一圈。

## 使用與診斷

使用原本的 `v23_mission_entry.py` 入口，新增適配器會自動啟用。
`--koala-root` 必須指向 `g2_prepare_koala.py` 建立的固定e8766f0完整runtime，入口檢查manifest與來源SHA256。
較舊或未準備的checkout會明確拒絕，不會默默退回固定後退。
仍需正常的 `--real --i-am-beside-the-robot` 才可能動作；本輪沒有執行該命令。

輸出 `mission/post_place_reentry.json`，成功或失敗都保存：每段位置、實際退距、是否具備轉向餘裕與最終錯誤。
入口報告亦保存適配器來源SHA256，原koala來源指紋保留。

若直退60cm內找不到同時可巡航與可轉向的位置，流程不會先退固定距離再反覆嘗試轉向。
此時應調整投放接近角度，讓投放姿態有一條可退回的出口走廊；或在接近時保存並驗證完整路徑，沿路徑倒退到已知準備點。
本輪實作的是有界直退及確認，沒有假裝已具備任意曲線路徑倒退。

## 離線驗證

```
python -X utf8 -m pytest tests/test_g2_patrol_reentry.py tests/test_v23_mission_entry.py -q
```

案例涵蓋：退20cm中心合法但仍不能轉，繼續退至27cm後接回；每段多走4cm時依實際量提前完成；
原本已合法時不再固定退20cm；6cm圈內的遮罩缺口；定位修正不算進度；持物、外部client、過期定位、owner變更及無實體退路時拒絕。
實車尚未驗收。

定位短暫失效時另套用 [任務恢復閘](MISSION_RECOVERY_2026-10-22.md)，保留已實際移動的退出進度。
