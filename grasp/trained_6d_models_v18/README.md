# grasp v18 — 高視野 C3 夾取姿態(已暫存,尚未啟用)

## 這是什麼

解決「v17 夾取初始姿態太低、看不到物體」的重訓成果。

| | v17(目前實際在跑) | **v18(本目錄)** |
|---|---:|---:|
| 相機離地 | 14.6 cm | **22.7 cm** |
| 夾取中心離地 | 7.5 cm | **14.5 cm** |
| 相機俯角 | 75.2° | **86.7°** |
| 地面可視(絕對) | 18.5 – 27.4 cm | **19.6 – 33.0 cm** |
| 可抓帶覆蓋 | 56% | **84%** |

模擬驗收:確定性 **97/100**(獨立 seed、部署區 x 0.20–0.33 / y ±0.10),九宮格全部 ≥83%。

## ⚠️ 現在還沒有啟用,這是刻意的

本目錄只是**暫存**。`x3plus_real_grasp.py` 仍指向 v17,整台機器維持在完整可用的 v17 狀態。

**最危險的組合是「v18 權重 + v17 姿態」**——第一筆 observation 就落在訓練分布外,手臂可能直接往地上壓。權重與姿態必須**一起換,或都不換**。

## 啟用前必須完成的實機 gate

1. **實機 FOV**:用下方 waypoint 開到 C3,尺規量實際可視範圍
2. **實機 reach**:量 C3 姿態下實際搆得到的最近/最遠地面點
3. **定出實際部署區** = FOV 窗 ∩ reach,並重新量 reach guard(舊的 0.15m 對新姿態無效)
4. **C3 專屬 homography**(9 個 fit + 3 個 holdout)
5. 以上都過,才把 `grasp_home_deg` 與 model/vecnorm 路徑**一次一起改**

⚠️ 使用者實測:v17 的真實 FOV 是夾取中心前 **+8~+20cm**,而 URDF 模型算出來是 −1~+8cm——**真實視窗比模型往前約 9~12cm**。所以 C3 的實際視窗預期在 +9~+22cm 左右,不要直接套模擬值。

## 角度慣例陷阱

「比較高」的姿態,S2 的 **API 值反而比較大**,App 顯示值反而比較小:

```
            送伺服(API)      App 螢幕顯示
v17(低)      S2 = 32.7        S2 = 147.3
v18(高)      S2 = 67.1   ↑    S2 = 112.9   ↓
```

因為 Rosmaster 對 S2/S3/S4 內部鏡像(App 顯示 = 180 − API)。

最可靠的確認方式**不是看數字,是看側面輪廓**:v18 應該是大臂立起、前臂抬平、手腕垂直下垂。若手臂仍壓得很低、前臂斜插地面,就是角度慣例弄反了,立刻停下。
另一個快速檢查點:v18 的 S3 與 S4 **相同**(9.79/9.79),v17 則不同(9.786/32.704)。
